How a project runs

Brief, build, check, ship: the same loop every project of mine goes through.

Signed off

Map it

We walk through the process as it runs today: where it fails, why, and who signs it off. The map and the definition of a correct result are written down and agreed before anything is built.

Build and check

Agents do the work and a separate step tests every output against that definition. Anything that fails is retried or routed to a person, never sent on silently.

Run and log

Every run is logged, so you can see what happened and why. The cost per run has a cap agreed in advance, and the workflow stops rather than overspends.

Questions about AI automation

What does AI automation cost?

It depends on the process and the tools it touches, so I quote per project. Describe what happens today and what goes wrong, and I reply within one working day with how I would approach it.

Which processes are worth automating first?

The ones that repeat every day, follow rules a person can write down, and hurt when they are missed: lead intake, weekly reporting, and checking documents before they go out are the usual starting points.

What happens when the AI gets something wrong?

A separate checking step tests every output against a written definition of correct. Anything that fails is retried or sent to a person, and the failure is logged so its cause can be fixed.

Do I have to change the tools my team uses?

No. The workflow is built around the tools you already use, such as email, web forms and spreadsheets, rather than asking your team to switch.

Who builds it?

I do, through Virin Digital, my studio in Kuala Lumpur. I work with businesses across Malaysia; most of the work happens online.

Why should I trust AI with a real process?

You should not trust it blindly. AI output often looks right when it is wrong, so every workflow I build has a separate check on each result, sends anything that fails to a person, and logs every run so a mistake can be traced to the step that let it through.
